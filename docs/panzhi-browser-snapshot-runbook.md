# 盼之原生筛选快照操作手册

盼之列表接口带页面签名和浏览器风控，软件不读取 Cookie、不导出登录态，也不绕过验证。默认由用户 Chrome 中安装的扩展操作页面自己的价格筛选，再把可见商品卡片提交给只监听本机的接口。

## 默认自动流程

日常刷新由 `extensions/panzhi-auto-refresh/dist/` 中的 Chrome 扩展领取：它只选择一个确定的盼之标签页（没有时只新建一个）。正常任务直接复用该标签当前已加载的 SPA 结果，不刷新或同地址导航；只有恢复非验证状态的未完成租约、地址不规范或租约丢失时才重置页面。每次执行使用唯一运行代号，新的 runner 会让遗留 runner 停止。扩展随后自动核对原生筛选、读取可见商品卡片并提交到 `http://127.0.0.1:4310`。任务、租约和计划保存在本地 SQLite；API 或 Chrome 重启后会续接同一个未完成任务，不需要重新点菜单。出现登录、滑块或验证码时，扩展停止采集、聚焦该标签页并通知用户；用户完成验证后自动从筛选阶段继续，期间不会刷新验证现场。一次性安装和断线排查见 [扩展说明](../extensions/panzhi-auto-refresh/README.md)。

下面的人工步骤只用于页面结构诊断或扩展不可用时验证手工快照接口，不是常规刷新入口。

常规后台刷新会对盼之返回 `browser_snapshot_required`，不会把 SSR 页面里未筛选的首批商品冒充为完整结果。当前公开前端的原生列表 API 需要浏览器生成的 `Sign` / `PZTimestamp` / `Random`，无签名请求会返回阿里云 WAF 验证页。系统因此保留上一次可信快照，等待下面的浏览器快照流程，而不生成或重放平台签名。

1. 打开 `https://www.pzds.com/goodsList/391/6`，需要登录时由用户本人完成；Codex 不读取密码、验证码、Cookie、localStorage 或认证请求头。
2. 在页面价格区间中把最低价填为 `1900`、最高价填为 `4000`，并选择“可二次实名”。在“特战干员外观”中同时勾选“骇爪-维什戴尔”和“露娜-黑天际线”，并把该组的多选模式保持为“全部都要有”（满足所有已选条件）后执行筛选。确认页面仍显示“三角洲行动”、可二次实名、两个价格输入框和两个勾选项的可见状态完全一致。
3. 快照中的原生筛选证明必须记录 `secondRealNameFilter: { label: "可二次实名", selected: true }`，并同时记录以下精确值：字段 `22858` / `特战干员外观` / `CHECKBOX`，请求映射字段 `22858`，多选语义 `ALL` / `全部都要有`，以及选项 `1038173` / `骇爪-维什戴尔` / `SA200018` 和 `1035794` / `露娜-黑天际线` / `SA200003`。实名证明缺失、未选中，或红皮选项缺项、重复、ID/文案不匹配，都会被服务端拒绝。
4. 快速增量从当前结果开始向下滚动，达到 60 个唯一商品或 6 次加载中的任一上限后停止；完整刷新继续滚动到连续两次没有新增商品。每次都等待页面完成加载，不使用固定高速循环或猜测内部分页接口。若平台弹出滑块验证，立即停止自动操作，由用户亲自处理。
5. 仅读取商品卡片的公开可见字段：商品 ID、规范详情 URL、标题、卡片文本和价格。不要打开开发者工具读取网络请求、签名、Cookie 或会话存储；也不得从这些私有状态猜测筛选证明。
6. 向本机 `POST /api/sources/panzhi/browser-snapshot` 提交模式、筛选证明、加载次数、唯一卡片数、结束原因和卡片数组。快速增量使用 `quick` / `quick_window`，完整自然结束使用 `deep` / `no_growth_twice`；被验证拦住时使用 `captcha_required`，软件会诚实发布为部分结果而不会冒充完整扫描。服务端要求精确的 `1900`/`4000`、可二次实名与原生干员外观证明、唯一 ID/URL、规范盼之链接，并限制请求为 1 MiB。
7. 服务端只发布 ¥1,900–¥4,000（含边界）的商品。盼之有时会在筛选结果顶部插入区间外置顶商品；这类卡片会计入观测数但由本地二次校验丢弃，并在响应的 `droppedByPrice` 中显示数量。若快照数量相对旧基线骤降，异常保护会隔离本轮而不是覆盖旧候选。
