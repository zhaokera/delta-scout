# ADR 0001：轻量列表与保守人工偏好

- 状态：已采用
- 日期：2026-08-01

## 背景

候选列表原先直接返回完整商品对象。23 条均衡候选约 346KB，200 条完整合格视图约 2.60MB，已淘汰视图约 3.28MB；大部分体积来自只有详情页才使用的原始描述和证据正文。

人工淘汰事件已经保存固定原因，但只会排除单个商品，不会兑现“以后根据原因辅助判断排名”的需求。另一方面，交易猫浏览器刷新在判断详情能否复用时会解析全部旧商品，而实际只需要本轮预算内的商品编号。

## 决策

1. `GET /api/listings` 只返回决策摘要，保留价格、皮肤资产、安全状态、评分、稳定性和人工决定；省略原始描述、证据正文、解析提示正文和评分解释。`GET /api/listings/:key` 继续返回完整详情，前端在用户打开账号时并行读取详情与历史。
2. 人工偏好作为读取时的排名覆盖层，不改写可信采集快照。系统只泛化“价格虚高、M7 不值、红皮不合适、安全风险、资产不足”五类结构化原因；“卖家问题”和“其他”缺少可靠的卖家或语义特征，只排除原商品，不扩散。
3. 每个相似负反馈只调整 1 分，同一原因最多 4 分、累计最多 8 分。调整只影响推荐总分和排序，不改变硬条件、基础价值、安全得分或风险等级；恢复人工淘汰后，对应影响立即消失。
4. 交易猫详情复用只按本轮必要商品的稳定 key 查询 SQLite，不再读取和解析整个来源快照。

## 取舍

- 摘要/详情分离增加了一次按需请求，但显著减少首屏和切换视图的 JSON 传输及解析；本地详情请求与历史请求并行，交互延迟可控。
- 人工反馈不做自动权重重训，避免少量样本改变全局评分。相似规则和扣分上限保持可解释，代价是不能理解自由文本中的复杂偏好。
- 偏好覆盖层在读取时计算，使恢复立即生效且不污染历史快照；当前数据规模下计算成本远小于重复传输完整证据。

## 失败与安全边界

- 完整详情读取失败时继续显示轻量摘要并明确提示，不把缺失正文当成已核验证据。
- 偏好模型无法改变准入、风险等级或平台原始数据，也不会依据“卖家问题”惩罚整个平台。
- 列表摘要不包含登录状态、Cookie、令牌或其它浏览器私密数据；详情接口仍只返回已存储的公开商品证据。
