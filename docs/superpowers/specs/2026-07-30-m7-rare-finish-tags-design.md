# M7 稀有模板标签与价值评分设计

## 目标

Delta Account Scout 从三平台公开商品的可追溯备注/描述证据中识别 M7 皮肤的三类高价值模板：

- 珠光
- 炫彩
- 糖果（包括“糖果纸”）

命中后保存结构化标签和原文证据，在候选列表与详情中醒目展示，并在不改变购买安全评分的前提下，把稀有模板纳入账号价值评分。

## 已确认决策

采用“精准 Tag + 8 分 M7 稀有模板价值”的方案：

- M7 品质分从原来的最高 35 分调整为最高 27 分。
- M7 稀有模板独立计入最高 8 分。
- M7 相关价值上限仍是 35 分，账号价值总分仍是 100 分。
- 购买安全、数据完整度和综合分权重保持不变。
- 三种模板同时出现时保存全部标签，但稀有模板分不叠加，仍为 8 分。

## 真实数据约束

当前快照中有大量包含“珠光 / 炫彩 / 糖果”的文本，但不少词语描述的是巨浪、MP7、AUG、挂饰、赛季 3×3 或收藏品。仅凭账号任意备注包含关键词会产生大量误报。

可信正例包括：

- `珠光粉m7`
- `白灯糖果纸m7`
- `极品炫彩镭射M7`
- `M7极品A 400发AWM子弹 7000点券 全炫彩`
- `M7的局内表现效果很好炫彩渐变`
- `棱镜攻势M7—极品B糖果纸`

应排除的反例包括：

- `M7是镭射玫瑰金... AUG是... 炫彩拉小宅`
- `M7... 巨浪是蓝紫粉炫彩`
- `极品M7... 炫彩MP7`
- `有三个赛季的炫彩3×3`
- `炫彩挂饰`

## 领域模型

新增枚举：

```ts
type M7RareFinish = "pearl" | "iridescent" | "candy";
```

`Listing` 新增：

```ts
m7RareFinishes: M7RareFinish[];
m7RareFinishEvidence: EvidenceRecord[];
```

字段要求：

- 数组按固定顺序 `pearl → iridescent → candy` 输出并去重。
- 老快照缺少字段时安全迁移为 `[]`。
- `m7RareFinishEvidence` 只保留实际支持标签的原文记录。
- 标签本身不能证明 M7 为极品，也不能改变硬筛选结论；只有现有 M7 解析器确认 `m7PrismStatus === "peak"` 的账号才可能进入候选。

可信历史快照与关键字段变化新增 `m7RareFinishes`。重复账号指纹仅在标签非空时包含该字段：旧账号和新扫描都没有标签时保持原指纹；首次发现可信标签时产生预期中的变化。

## 识别规则

新增独立的纯函数：

```ts
parseM7RareFinishes(records: EvidenceRecord[]): {
  finishes: M7RareFinish[];
  evidence: EvidenceRecord[];
}
```

处理步骤：

1. 将每条证据按换行、中文/英文逗号、分号和斜杠拆成短句，保留括号内部文本。
2. 在短句内用词法边界 `(?<![A-Za-z0-9])M7(?![A-Za-z0-9])` 定位通用 M7 提及，避免把 `XM7`、商品编号或更长型号误认为 M7。允许：
   - `M7`
   - `M7战斗步枪`
   - `M7棱镜攻势`
   - `M7战斗步枪-棱镜攻势S2`
3. 定位关键词：
   - `珠光` → `pearl`
   - `炫彩` → `iridescent`
   - `糖果` 或 `糖果纸` → `candy`
4. 对每个关键词，在前后各 24 个可见字符内定位所有武器/物品主体，并把关键词归给距离最近的主体。只有最近主体明确为 M7 且不跨短句边界时才命中；并列最近或主体含糊时保守跳过。
5. 主体至少包括：M7，以及 `巨浪`、`MP7`、`AUG`、`KC17`、`K416`、`M250`、`腾龙`、`挂饰`、`3×3`、`33`、`收藏品`、`手办`。同时识别独立的常见大写字母数字武器型号，避免新型号造成误报。
6. 若同一句有多个主体或多个关键词，分别计算最近距离；主体位于关键词前后都参与比较。因此 `极品M7...炫彩MP7` 归属 MP7，`M7...巨浪是蓝紫粉炫彩` 归属巨浪，均不打 M7 Tag。
7. 关键词可位于 M7 前后，例如 `珠光粉m7`、`炫彩镭射M7` 与 `M7全炫彩` 均可识别。
8. 若关键词前 4 个可见字符或 M7 与关键词之间出现 `无`、`非`、`不是`、`不带`、`没有`、`未有`、`不含` 等否定词，则跳过，例如 `M7无炫彩`、`不是糖果纸M7`。
9. 当前 `EvidenceRecord` 没有标题/摘要/详情来源字段，因此所有可追溯的卖家原始证据（标题、摘要和详情备注）都可参与识别。不得从评分、价格、其它账号或模型猜测推断标签。

距离 24 用于覆盖“`M7的局内表现效果很好炫彩渐变`”等真实写法，同时阻止跨越长段落拼接。最近主体、否定词和词法边界优先于距离。

## 采集与持久化

协调器在合并摘要和详情证据后调用 `parseM7RareFinishes`，与 M7 品质、角色红皮和巨浪解析处于同一阶段。

写入 SQLite 的仍是现有完整 Listing JSON，不新增独立表。`ListingSchema` 默认值负责读取历史 JSON。新鲜扫描写入完整结构；旧 Listing 和历史 `snapshot_json` 缺少新字段时都补为 `[]`。

关键字段历史：

- 快照保存 `m7RareFinishes`。
- 变化标签显示为“`M7 稀有模板`”。
- 比较时按固定顺序序列化，避免顺序差异产生虚假变化。
- 历史比较先把缺失字段规范成 `[]`，旧快照空值与新快照空数组相等，不产生虚假变化。
- 物质指纹只在 `m7RareFinishes` 非空时加入标签字段，避免本次模型升级让所有无标签账号都被标成变化；首次发现非空标签仍产生预期变化。
- 旧快照保留原评分。只有新的可信扫描才按 `27 + 8` 重算；被验证码阻塞而沿用旧来源数据时，不补造标签或重算旧账号。

## 评分

M7 品质分：

| 品质 | 分数 |
| --- | ---: |
| S | 27 |
| A | 23 |
| B | 18 |
| C | 14 |
| 品质未知 | 0 |

M7 稀有模板分：

| 状态 | 分数 |
| --- | ---: |
| 至少一个可信标签 | 8 |
| 未识别 | 0 |

账号价值：

```text
M7 品质 27
+ M7 稀有模板 8
+ 角色红皮 20
+ 巨浪 15
+ 价格 20
+ 资产 10
= 100
```

综合分仍为：

```text
账号价值 × 55% + 购买安全 × 35% + 数据完整度 × 10%
```

这样一个稀有模板最多使综合分增加 4.4 分，同时不可二次实名、无包赔、封禁备注等安全风险仍由独立安全维度决定。

为兼容旧评分 JSON，`ScoreSchema.parts` 不新增必填字段，继续复用现有最高 35 分的 `parts.m7`：

```text
parts.m7 = M7 品质分（最高 27）+ 稀有模板分（0 或 8）
```

总值仍封顶 35 分，三种标签不叠加。价值原因分别解释品质与模板两个组成部分。

价值原因示例：

- `M7 极品A，价值 23.0/27`
- `M7 稀有模板：珠光 · 糖果，价值 8.0/8`
- `M7 稀有模板待核验，价值 0.0/8`

## 界面

### 候选列表

在现有 `M7 · 极品A` 下方或同一区域展示紧凑高亮 Tag：

- `珠光 M7`
- `炫彩 M7`
- `糖果 M7`

样式使用当前荧光黄绿色体系，但与“可二次实名”安全状态分离。Tag 带可访问文本，不只依赖颜色。

### 详情

M7 证据区增加“高价值模板”行：

- 命中时展示所有 Tag。
- 展示一条或多条支持标签的原文证据，关键词高亮。
- 未命中时显示“稀有模板待核验”，不得显示“没有”。

评分明细保持单项 `M7 综合价值 x / 35`，下方价值原因分别显示：

- `M7 品质 x / 27`
- `M7 稀有模板 x / 8`

### 筛选

本功能不新增筛选项。用户已要求 Tag 与重点关注，现有“皮肤价值高优先”和推荐分排序会自动反映新价值分；新增筛选属于后续需求。

## 错误与安全边界

- 关键词存在但无法与 M7 建立可信关系时，不打 Tag，不加分。
- 只发现“糖果”而没有 M7 时不命中。
- 同一句明确指向巨浪、MP7 等其它主体时不命中 M7。
- 解析异常不得阻断整个来源；返回空标签并保留原证据。
- Tag 不是价格承诺。界面只表达“高价值模板信号”，不显示推测市价。
- 不改变验证码、登录、公开只读采集和不自动下单边界。

## 测试

### 领域测试

- 三个关键词分别在 M7 前后均能识别。
- `糖果纸` 规范成 `candy`。
- 多标签去重并按固定顺序。
- 距离过远、跨句、其它武器、巨浪、挂饰、3×3、收藏品反例不命中。
- 其它主体位于关键词前后时都能正确归属，覆盖 `极品M7...炫彩MP7` 与 `M7...巨浪...炫彩`。
- `XM7`、商品编号和 `M7无炫彩`、`不是糖果纸M7` 等边界/否定反例不命中。
- 标题、摘要和详情备注中的可追溯卖家原文都使用同一条识别规则。
- 标签不改变 M7 `peak / premium / unknown / conflicting` 结论。

### 模型与持久化

- `ListingSchema` 接受新字段。
- 老 JSON 缺少字段时迁移为空数组。
- 仓储往返保留标签和证据。
- 历史快照、字段变化和稳定指纹包含标签。
- 旧历史缺字段与新快照空数组比较时不产生虚假变化，首次出现非空标签时产生预期变化。

### 评分

- 普通 S/A/B/C 的 `parts.m7` 分别得到 27/23/18/14。
- 任一或多个标签只加 8 分一次。
- `parts.m7` 最终为品质分与稀有模板分之和并封顶 35，不新增破坏旧 JSON 的必填评分字段。
- 安全分与风险等级不受标签影响。
- 带稀有模板的其它条件相同账号排名更高。

### 客户端

- 列表展示对应中文 Tag。
- 详情展示 Tag、原文证据和评分拆分。
- 无标签时不伪造 Tag，并显示待核验。

## 完成标准

- 三类标签从可追溯证据准确解析并持久化。
- 候选列表和详情都有清晰 Tag 与证据。
- 评分按 27 + 8 规则工作，安全维度不变。
- 自动化测试、类型检查和生产构建通过。
- 至少一轮真实刷新完成并报告三平台状态与命中统计。
- 浏览器中的候选台完成视觉和交互验收。
- 代码与文档提交并推送到 `master`。
