# 二次实名作为唯一安全判断设计

## 背景

当前界面的“安全证据”覆盖率同时统计二次实名状态和验号时间，风险等级也会因验号时间缺失或超过 30 天而变化。验号时间在不同平台之间并不稳定、不可直接比较，容易让 `2 / 2` 被误解为两项安全条件均已通过。

## 决定

购买安全只看 `secondRealNameAvailable`：

- `true`：安全证据完整，显示 `安全证据 1 / 1`；无封禁备注时风险为低。
- `false`：安全证据完整，仍显示 `安全证据 1 / 1`；风险为高。
- `null`：安全证据缺失，显示 `安全证据 0 / 1`；风险为“安全证据不足”。
- 任意封禁备注继续优先判定为高风险。

验号时间和永久包赔继续展示为购买参考，但不参与：

- 推荐分；
- 购买安全分；
- 安全证据覆盖率；
- 风险等级。

购买安全分保持现有分配：明确可二次实名为 `40 / 40`，不可或未知为 `0 / 40`。账号价值规则不变。数据完整度中的安全信息项只检查二次实名是否已知，不再因验号时间已知而得分；其它数据完整度项目及权重不变。

## 实现范围

在领域评分逻辑中：

1. 安全证据覆盖率只检查 `secondRealNameAvailable !== null`，总项数固定为 1。
2. 风险等级只依据二次实名状态和封禁备注，不再接收或判断验号时间、证据项数量和安全分。
3. 数据完整度的安全信息项只依据 `secondRealNameAvailable !== null`，验号时间与永久包赔都不能直接或间接改变推荐分。
4. `Score` 数据结构保留现有 `coverage` 对象形状，但把 `knownSafetySignals` 的允许范围改为 0–1，并把 `totalSafetySignals` 固定值改为 1。
5. 保留验号时间的解析、存储、详情展示及历史记录，不删除现有字段。

列表、详情和候选对比继续使用评分结果中的 `coverage` 渲染，因此会显示 `0 / 1` 或 `1 / 1`。排名诊断页当前写死 `/ 2`，必须同步改为 `/ 1`。

## 验证

领域测试覆盖：

- 可二次实名且无验号时间仍为低风险、`1 / 1`；
- 可二次实名且验号时间陈旧仍为低风险；
- 不可二次实名即使有验号时间也为高风险、`1 / 1`；
- 二次实名未知即使有验号时间仍为证据不足、`0 / 1`；
- 封禁备注继续覆盖其它状态并判为高风险。
- 仅改变验号时间或永久包赔时，购买安全分、证据覆盖率、风险等级、数据完整度和总推荐分均不变。

数据结构测试与验收脚本更新 `coverage` 的范围和固定分母。客户端测试更新列表、详情和排名诊断中的安全证据文案为 `/ 1`，并确认验号时间仍以“仅作参考、不参与评分”展示。

## 非目标

- 不改变平台采集器对二次实名、验号时间或永久包赔的解析规则。
- 不改变候选准入条件；明确可二次实名仍是合格候选的硬条件。
- 不删除验号时间或永久包赔筛选、历史与详情信息。
