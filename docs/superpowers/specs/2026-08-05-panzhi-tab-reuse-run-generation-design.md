# 盼之标签复用与运行代号设计

日期：2026-08-05

## 背景与结论

扩展当前会在每次领取新任务后重载已经存在的盼之目录标签。实机诊断表明，手动打开的目录页能很快得到商品列表，而扩展重载后经常只剩筛选框和空的虚拟列表。继续增加等待时间不能解决这个差异。

改为：正常任务直接复用已经加载完成的唯一盼之标签，不执行刷新或同地址导航；只有扩展重启恢复未完成租约、租约丢失或标签地址不合规时才执行页面级恢复。内容脚本使用不可复用的运行代号，使新任务能够取消遗留 runner，而不依赖刷新页面来取消 JavaScript。

## 行为设计

### 正常领取

- 继续按既有确定性规则选择一个盼之目录标签。
- 标签已经位于严格规范地址时，保持 DOM、SPA 状态和结果列表，不调用 `tabs.reload` 或 `tabs.update({url})`。
- 标签不存在时创建规范地址；标签只匹配目录路径但带 query/hash 时导航到严格规范地址。
- 执行前激活所拥有的标签，随后向内容脚本发送任务模式和新运行代号。

### 恢复与验证码

- Service Worker 重启后恢复到非验证码状态的有效租约时，对所拥有标签硬刷新一次，再从筛选阶段重新执行。
- `awaiting_user_verification` 状态绝不刷新或导航，保留登录/验证码/滑块现场，用户完成后自动继续。
- 租约丢失时把所拥有标签重置到规范地址，终止旧页面上下文，且不提交旧快照。
- 不绕过验证码，也不读取 Cookie、密码、localStorage、网络签名或页面脚本。

### 运行代号与取消

- 后台每次真正启动页面任务时生成唯一 `runId`，通过 `panzhi-run-v3` 发送。
- 内容页全局桥保存当前 `runId` 和对应 Promise。同一 `runId` 的重复消息复用同一 Promise；不同 `runId` 立即成为新一代执行。
- 页面 runner 在阶段切换、等待前后、点击前后、每轮采集和最终快照前检查 `isCurrentRun()`。
- 旧 runner 发现代号失效后返回 `superseded`，不得继续点击、采集或提交。后台把当前命令意外收到的 `superseded` 当作可重试错误，不伪造成功。
- 重新注入内容脚本时复用同一个页面全局桥状态，因此遗留模块闭包也能看到新代号并停止。

## 协议与测试

- `PageRunnerResult` 增加 `superseded` 结果；`PageRunnerDependencies` 增加 `isCurrentRun`。
- 后台依赖增加可注入的 `createRunId`，生产环境使用 `crypto.randomUUID()`，测试使用确定值。
- 测试必须证明：正常复用不刷新、恢复租约仍只刷新一次、验证码恢复不刷新、后台发送 v3 与 runId、同代执行去重、异代执行取消旧 runner、取消后不再触发下一次页面动作。
- 保留现有筛选证明、采集上限、验证码、租约和提交回归测试，并执行扩展构建、类型检查及排除审计 worktree 的全量测试。

## 失败处理

- 标签页不存在或地址不规范：创建或导航后等待完成。
- 恢复硬刷新失败：本轮报错并按现有退避重试，不提交数据。
- runner 被新代号替代：旧执行结束；当前执行继续。若当前后台命令自身收到替代结果，则报 `operation_cancelled` 并重试。
- 页面结构仍不满足严格选择器：保持结构漂移失败，不放宽筛选证明。
